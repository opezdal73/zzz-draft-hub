# Реализация текущего ТЗ (итерация 1)

## В этой итерации
- Каталог амплификаторов заменён списком из последнего сообщения пользователя: 100 записей с редкостью и классом.
- В Cost Manager добавлены поля M0–M6 для каждого агента.
- В Cost Manager добавлены поля R1–R5 для основного коста амплификатора, отдельные R1–R5 для оффбилда и индивидуальные R1–R5 для выбранного агента.
- В «Мои ростеры» добавлено окно «Ростер аккаунта» с полным каталогом агентов/амплификаторов; создание игровых ростеров фильтруется по отмеченной коллекции.
- Добавлена миграция `supabase/player_account_inventory.sql`.
- Исправлены два вывода `Set` в `MatchSeries.tsx`, которые давали TypeScript `unknown[]`.

## Настройка Supabase
Выполнить `supabase/player_account_inventory.sql` в Supabase SQL Editor. Ростер аккаунта сохраняется в таблицу `player_account_inventory`.

## Важные ограничения этой итерации
- Автоматический расчёт стоимости в BO2 пока не переключён на новый выбор M/R + specialty; новый интерфейс редактирует и хранит эти поля в состоянии приложения.
- ID амплификаторов обновлены для каталога; старые сохранённые ростеры, содержащие старые ID амплификаторов, могут потребовать повторного выбора амплификаторов.
- В этой среде сборку не удалось запустить: архивные `node_modules` не содержат исполняемый пакет TypeScript для Linux. После распаковки выполнить `npm install`, затем `npm run build`.

## Draft cost integration update
- Draft room roster selection reads the current catalog/cost overrides from app state; authenticated clients load the shared costs from Supabase.
- Roster selection displays the sum of each agent's configured M-level cost and blocks selection when an agent level has no configured cost or the sum is outside the global min/max roster cost.
- Room side summaries use the level-specific costs from the saved roster snapshot instead of always using `baseCost`.
- BO2 squad amplifier choices are restricted to amplifiers saved in that player's selected roster snapshot. Amplifier cost resolution checks the agent-specific override first, then matching-specialty base rank cost or off-build rank cost, then legacy fallback cost.
- Cost Manager now uses the shared `system_settings` row `cost_config`; apply `supabase/shared_cost_config.sql` to enable shared reads/writes and Realtime updates. Admins and Cost Managers can write; all authenticated accounts can read. DraftRooms receives the live catalog from the app state instead of initializing a separate browser-local copy.
- Server-side validation still needs a follow-up so the database enforces the shared costs when roster and match actions are submitted.

## Исправление драфта и ростеров (`supabase/draft_roster_integrity_fix.sql`)
Применять один раз, после всех остальных миграций (включая `draft_roster_rules_fix.sql` и `bo2_second_game_ready.sql`). Не запускать старые драфт-миграции после неё: они переопределяют те же функции.

- **Правило пулов:** бан — только из ростера соперника; обычный пик — только из СВОЕГО ростера; зеркальный пик — только агент, которого пикнул соперник И который входит в ростер зеркалящего игрока (дважды отзеркалить одного персонажа нельзя). Раньше пик был разрешён из обоих ростеров (клиент `unionRoster` и серверная проверка). Правило проверяется и в `DraftRooms.tsx`, и в `submit_draft_action`.
- **BO2, игра 2:** комната теперь получает оба снимка ростеров (`roster_snapshot_*`), поменянные местами вместе с игроками; раньше снимков не было, уровни и амплификаторы терялись. Дополнительные баны за разницу костов пересчитываются для поменявшихся сторон (раньше копировались из игры 1 и доставались не тому игроку).
- **Турниры:** `create_tournament_draft_room` берёт ростеры из одобренной заявки (`tournament_registration_requests.roster_snapshot`), а не из данных клиента. Для администратора присланные снимки остаются запасным вариантом.
- **Фиксация ростера:** `select_saved_roster_for_draft` не работает для турнирных комнат и комнат игры 2 BO2.
- **Закрытые лазейки:** устаревший RPC `save_draft_roster` отключён (менял список агентов без уровней); политика вставки в `draft_rooms` разрешает клиенту создавать только пустую комнату в статусе `waiting`.
- Минимум агентов при выборе ростера снова проверяется по `draft_rooms.min_agents` (версия из `configurable_min_agents.sql`).
- Если нужен общий пул пиков, как раньше: в `DraftRooms.tsx` верни `ownRoster` → объединение двух ростеров в `pool`, а в `submit_draft_action` — проверку пика по `roster_one || roster_two`.

## BO2: отряды для обеих игр и лимит таймера (`supabase/bo2_squads_and_timer_fix.sql`)
Применять один раз ПОСЛЕ `draft_roster_integrity_fix.sql`; старые BO2-миграции после неё не запускать (они переопределяют `guard_bo2_match_series` и `create_bo2_second_draft`).

- **Отряды второй игры.** После драфта игры 2 появляется свой экран сборки отрядов: новая фаза серии `squads2`, колонки `game2_squad_one/two`, `game2_squads_ready_one/two`. Поток: `squads` → `game1` → (драфт игры 2) → `squads2` → `game2` → `completed`. Раньше `create_bo2_second_draft` сразу ставил `game2`, поэтому экрана не было.
- **Расстановка вручную.** Агенты больше не ставятся автоматически: сначала все выбранные в драфте лежат в пуле, игрок сам кладёт их в отряд 1 или 2. В отряде не более 3 агентов (клиент + сервер), амплификатор выбирается компактным списком в строке агента. Для «Готов» нужно распределить всех выбранных агентов; назначенные амплификаторы по-прежнему ограничены бюджетом.
- **Таймер не более 10:00** в обеих играх: поле минут ограничено 10, 10:01 и выше отклоняются в интерфейсе, на сервере — `check`-ограничения (`NOT VALID`, старые записи не трогаются) и проверка в триггере.
- **Серверные проверки серии:** агенты в отрядах — только выбранные этим игроком в драфте именно этой игры; нельзя редактировать отряды не в своей фазе; игра 2 нельзя «перепрыгнуть» без сборки отрядов.
- **Защита от дублей:** уникальный индекс — не больше одной комнаты игры 2 на серию (если дубликаты уже есть, индекс пропускается с NOTICE; запрос для поиска дублей в комментарии файла).
- **Код:** правила расстановки и разбор таймера вынесены в `src/bo2Utils.ts`; `MatchSeries.tsx` переписан читаемо и получает каталог костов из `DraftRooms` (общие косты), а не из localStorage.
- Серии, которые уже в фазе `game2`, продолжаются как раньше (экран отрядов для них не появится).

## BO2: вторая игра в той же комнате и новая тема (`supabase/bo2_single_room_transition.sql`)
Применить один раз ПОСЛЕ `bo2_squads_and_timer_fix.sql`. Миграция сохраняет снимок завершённой первой игры, сбрасывает драфт в той же строке комнаты и меняет местами игроков и их ростеры для второй игры. ID комнаты и код приглашения остаются прежними; отряды второй игры собираются после её драфта. Идентичность игроков серии хранится отдельно, поэтому перестановка мест не меняет привязку таймеров и результатов. Старые BO2-серии с отдельной второй комнатой остаются доступны.

- Интерфейс второй игры перезагружает ту же комнату после подтверждения готовности обоими игроками.
- Визуальная тема сайта обновлена на чёрную с розовым неоновым акцентом для навигации, карточек, форм, драфта, ростеров, сетки турнира и модальных окон.
- Миграцию нужно выполнить в Supabase, чтобы режим одной комнаты заработал на опубликованном сайте.

## Амплификаторы: копии с отдельным пробуждением
Для отдельного уровня пробуждения каждой копии применяется `supabase/player_account_inventory_weapon_copies.sql` один раз в Supabase SQL Editor. Ростер аккаунта хранит уровень каждой копии; сохранённые игровые ростеры сохраняют выбранные уровни в JSON `w_engine_levels`. Старые записи поддерживаются: первая копия читает прежнее поле уровня по ID, отсутствующие уровни получают стандарт (A — R5, S — R1).

- При создании игрового ростера копии переносятся с индивидуальными пробуждениями из ростера аккаунта.
- В BO2 экран отрядов позволяет выбрать конкретную копию, показывает её пробуждение и считает кост именно для выбранного уровня и персонажа.
- SQL-защита серии хранит выбранную копию в составе отряда как `engine_copy_key`; это поле находится внутри JSON отряда, отдельная колонка не требуется.
